# Feature acceptance

Status distinguishes implementation, observed verification and external blockers. This is not a claim that the overall competition release gate has passed.

| Capability | Implemented behavior | Evidence / status |
|---|---|---|
| F1 intake/review | Bounded TXT/CSV/text-PDF, source blocks/hashes, exact quotes, editable critical IDs, explicit modes | Genuine AMD Gemma responses drove two fresh/revised synthetic notices through review, 500/800-unit plans and receipts. Raw IDs needed zero corrections; ambiguity probe limitation retained. Review was agent-operated, not independently human-validated. |
| F2 exposure | Confirmed/possible DAG traversal, unknown ancestry uncertainty, complete-scope exclusions, selectable navy graph, lineage table, stock reasons and source links | Exact 400 documented +100 uncertain +700 outside under v1. Merges/splits/rework, missing paths, duplicate paths and invalid cycles tested. Imported versioned events remain explicit in graph. |
| F3 comparison | Data-derived broad/required quantities and integer carrying values | v1 1,200 versus 500, €48,000 versus €20,000; €28,000 outside proposed broad hold. v2 800 and €16,000 excluded value. No savings claim. |
| F4 revisions | Immediate stale approval, current-source review, prior/new lots and quantity difference | v1→v2 and 500→800 observed in browser and installed app. Server rejects old approval before and after renewed scope. |
| F5 evidence queue | Missing ancestry requests ranked by unique inventory value, gap links, copyable draft, deduplicated total | Main queue: FG-C, 100 units/€4,000 maximum value potentially clarified. No request is sent. |
| F6 sandbox | Exact-digest approval, transactional current-version/action check, owner isolation, hold-only operations, idempotent receipt | API race/duplicate/stale/edited/unsupported/cross-session checks pass. Browser and installed desktop commit genuine local inventory changes and show receipt. |
| F7 orders | Explicit allocations with row IDs, due dates, linked stock and review reasons | 3 distinct open orders under v1 and 4 under v2, observed on both clients. Allocations never add to inventory totals. |
| F8 packet | Versioned sanitized JSON, historical sources/reviews/receipts, offline read-only review, new-draft promotion | Live-driven packets exported with both runs/receipts. Actual installed Windows import/save/reopen passed without dialog stubs. Existing offline/runtime and packet rejection evidence remains valid. |

F9 rehearsal, Evolus, OCR, ERP integration and other desktop targets are omitted. Hosted web distribution, public download URLs and completed submission remain open external gates. Genuine local AMD execution and actual Windows file-dialog checks now have evidence.
