# BatchFence 0.3.0 release evidence

Four connected modules are implemented: Quality Signals, Approved Knowledge, Controlled Recovery, and Corrective Action with Effectiveness. Shared foundations add scoped named pilot identities, PostgreSQL, source preservation, migration/restore tooling, bounded jobs, mapped imports, OCR review and typed receiving. The original incident path, conservative uncertainty, stale approvals and receipts remain.

The release is suitable for a synthetic public demonstration and an owner-controlled engineering pilot. It is not accepted for production inventory or a safety-critical context. The public free Render service has ephemeral storage. Desktop remains unsigned. The local pilot defaults to private access and requires owner-provisioned users and approved data use.

Fresh AMD evidence is in [live/README.md](live/README.md). The 24 frozen items were all exercised, with 20 actual model requests and four retrieval-only abstentions. Across the integrated and frozen work there were 27 attempts, one timeout, no automatic retries and no fixture substitution. Raw extraction exact matches were 6/12; knowledge pipeline matches were 11/12. These limitations remain visible. The context-fixed typed draft drove reviewed 700 proposed / 800 applied / exact 100 controlled sandbox recovery. The final signal explanation matched computed observations.

Regression, packaging, deployment identities and artifact hashes are recorded in the final release report after their checks complete. Previous v0.2.0 and v0.3.0-rc.1 artifacts remain recoverable and are not overwritten.

## Required human acceptance

- Quality professional reviews organization-specific scope/recovery policy and supported manufacturing context.
- Three unfamiliar operators complete the prepared counterbalanced task protocol; no participants or savings are invented.
- Owner provisions real scoped pilot identities, approves external AMD processing for any confidential data, and sets an off-device backup destination and RPO/RTO, then observes a restore.
- Operator completes native Windows file open/save/reopen and reviews unsigned-installer trust prompts. Automated dialog stubs do not count.
- Real enterprise integration remains unimplemented and unauthorized. The reference connector is local sandbox only.
- Owner privately rotates the provider credential that the portal exposed in a tool response during allowance inspection, then updates private local/Render configuration. No literal credential appears in repository evidence. Rotation is not performed automatically.
- Owner checks the authenticated event form's current media constraints and cutoff. No hackathon entry has been saved or submitted.

## Desktop profiles

The public Windows release defaults to `https://batchfence.onrender.com`, matching the web build. For a private pilot, start `docker compose -f ops/compose.pilot.yml up --build -d`, then launch the installed application from a shell with `BATCHFENCE_BACKEND_ORIGIN=http://127.0.0.1:8788`. See [pilot-operations.md](pilot-operations.md) for identity, source, backup and restore commands. Offline packets are read-only and grant no inference, approval or execution authority.
