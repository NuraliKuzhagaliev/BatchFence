# Data contracts and source review

All quantities use discrete whole pieces; money fields are integer cents. No automatic unit conversion. Templates: fixtures/enterprise/templates/*.csv. Existing legacy fixture headers still work through their original intake route. Mapped onboarding requires explicit column mapping, IANA timezone, source revision, observed timestamp and reviewed source; profile reuse does not reuse review authority. At most 500 rows / 2 MB per import. Ambiguous/nonexistent local DST times require an explicit UTC offset. Duplicated row IDs, cycles, overflow, unknown targets, bad denominators and resizing/removing held pools are rejected. Corrections preserve prior records and invalidate affected plans/baselines.

Inspections measure nonconforming units (not counts of multiple defects per unit): 0 <= nonconforming <= inspected, inspected > 0. Group by site, product, process, method, regime and defect family; pool_ids is a semicolon-separated list. Missing/unmatched genealogy must be reviewed; a chart alert never applies a hold.

PDF intake retains original bytes and text/page references. Scanned pages use Tesseract/Poppler in a bounded Linux subprocess. Original page PNG and TSV word boxes/confidence stay in the source store. All scanned pages require explicit visual confirmation of identifiers, quantities and completeness before narrowing/recovery. Text hashes are change detection only. Offline packets carry text/reviews, not every original page byte; the source backup remains necessary.

Typed receiving distinguishes supplier lot, stock pool, receipt ID, document ID, lineage row and unknown. Narrative mode requires the current model draft and explicit review. Structured-source review permits a reviewer to enter source-backed relationships directly. Complete replacement requires every superseded parent row, an exact quote, completeness confirmation and contradiction disposition. Partial/unknown evidence preserves uncertainty. Source occurrence alone is not semantic proof.

Procedure revision: immutable id@version, approved/obsolete/draft status, effective dates, products/processes and ordered exact passages with source hash. Conflicting applicable approved versions cause abstention. Answers retain exact quoted passage references as model proposals; recording a case check is a separate evidence review and invalidates prior case authority. Procedure text import is supported; there is no automatic PDF SOP approval.

Recovery: whole-pool incident restriction removal only. Snapshot binds case/evidence/inventory/hold/policy/procedure versions, proof and actions. Preparer and release approver must differ in pilot mode. Acknowledged execution records a separate receipt; original containment receipt is immutable and another incident's active reason keeps stock held.

Corrective action: investigation separates hypothesis from accepted cause; the plan freezes baseline/group/window/exposure/expected observations/maximum nonconforming rate/missing-data policy before implementation. Synthetic historical replay is explicit. Reviewed outcome needs sufficient comparable data, and measured change alone does not prove causation. Recurrence creates a reopening proposal requiring explicit review.
