# Vision contract review

Authenticated AMD TokenFactory User Manual, https://notebooks.amd.com/tokenfactory, inspected 18 October 2026 alongside the authenticated model catalog and usage API. No credentials were retained. This is managed AMD shared inference, not an owned AMD Cloud vLLM deployment.

The manual identifies the shared endpoint `https://developer.amd.com.cn/radeon/api/v1`, free experimental shared access with a hard daily nonmonetary points cap, OpenAI-compatible chat requests, and JSON object output. Gemma-4-31B-IT is described as a vision-language model; the image paragraph omits Gemma although the model table includes image capability. Historical successful image requests and the three current direct successes provide actual Gemma image evidence. `DeepSeek-V4.1-Flash` is explicitly listed for image input and is present under that exact catalog identifier. Generic catalog `free=false` flags differ from the authenticated event manual; the verified event allowance and enforced daily boundary govern this bounded work. Neither model names nor catalog flags establish own AMD allocation eligibility.

Image contract: user content contains `image_url` with `url: data:image/png;base64,...`, followed by the text task/schema; the system instruction is first. No expected transcription is supplied. Historical successful Gemma used JSON object mode. Current paired requests with and without that mode both succeeded, so JSON mode is not established as the cause.

Application limits are stricter than the documents available here: original <=2 MB; PNG/JPEG/WebP, one frame, dimensions16–4096, <=8 million pixels; bounded subprocess decode; EXIF orientation, RGB pixel copy and optional operator crop; metadata-free PNG <=4 MB. Retained input audit shows the failed images are ordinary single-frame RGB PNGs, 720x260 or720x330, with strict base64 round-trip and matching original/derived hashes. No undocumented provider image-size ceiling is claimed.

Label inference is direct from the BatchFence server to AMD. Evolus extraction/agent workflows are separate and unchanged; saved Evolus `own/gemma-4-31b-it` is not evidence that image bytes traversed Evolus. Text Gemma and the saved Evolus connection retain their existing model. Any image-only model selection is explicit and its actual requested/runtime IDs must be recorded; there is no silent fallback.

New bounded diagnostics retain endpoint, image MIME/byte count/hash, canonical request digest, HTTP status, latency, and sanitized provider error type/code/message. No authorization headers, image data URLs, hidden reasoning or keys are retained. Earlier HTTP500 records lack provider error bodies and request IDs and cannot establish a retrospective cause by themselves.

Render configuration is owned by the existing service settings, not a newly synchronized Blueprint. Current Render Environment Variables and Secrets documentation was retrieved as HTML after the Markdown fetch failed. MCP updates merge only specified keys (`replace:false`); activation must be verified after the resulting deployment. No key rotation, paid plan, new service or complete collection replacement is authorized or needed.
