# Limitations and release blockers — 0.1.1

- Local synthetic demonstration and review are ready. Production/public release acceptance is not complete. Docker/container/hosted persistence and download verification remain open; nothing was published.
- Raw AMD ambiguity booleans remain unreliable. Two new ambiguous notices yielded one wrong boolean interpretation and one citation rejection. Clear notices needed qualifier interpretation despite correct lot IDs. First generic Gemma failure has no typed root cause; two subsequent timeouts are explicit. No fallback masks failure.
- All candidates start unresolved and narrowing needs explicit source-backed review. Conservative English contradiction rules are not general entailment, can miss phrasing and can over-block mixed statements in one source block. Human review can still be wrong; source quotes and explanations do not prove semantic completeness. Missing model candidates and untruthful/incomplete record exports remain risks.
- Review uses anonymous session capability, not enterprise identity. Codex-operated acceptance checks are not independent human/customer validation. No manufacturing professional, actual production process, measured savings, safety or compliance certification is evidenced.
- Unresolved scope broad holds can over-contain. Outside evidenced scope never means certified safe. Operations only add sandbox holds; they cannot release existing stock or control an ERP/machine.
- TXT/strict CSV/selectable-text PDF only, within bounded sizes. No OCR, arbitrary spreadsheet/table interpretation or optional integrations. Dataset replacement remains staged until review and preserves existing holds.
- Windows x64 0.1.1 is unsigned and tested on one existing Windows 11 build 26200 host. Current native bridge tests use dialog stubs; real dialogs passed previously on 0.1.0. Recheck real dialogs on the exact binary before external distribution. Other operating systems, second-machine installation, signing and auto-updates remain unverified.
- Web and desktop sessions do not synchronize. Desktop capability is main-process memory only; restarting starts a new session. Use historical packets for handoff. Offline packets cannot analyze, approve, apply or queue writes.
- New AMD analysis/actions require the local backend; Python/model weights are not embedded. A public backend origin must be chosen, authorized, configured and repackaged before distributing to another person's machine.
- Docker diagnosis: com.docker.backend.exe failed at sailor-ingest.sock rename; AF_UNIX reparse tag 0x80000023, error 1920, engine pipe absent. Parent permissions already allow full control; no live owning Docker process was established. No permission/reset/socket/container/volume changes were made.
- Live packet hashes needed a Python/JavaScript number-format fix. Original rejected exports are preserved under ambiguity-fix/pre-fix-packets; use the reissued packets for opening. A hash detects changes but does not authenticate suppliers.
- Eight historical moderate development-only packaging advisories remain; no blind forced dependency changes were applied. Production npm audit had zero advisories at the recorded check. New rfc8785 0.1.4 is pinned and Apache-2.0 licensed; no new comprehensive security audit is claimed.
- Updated 0.1.1 media labels fresh/live, historical and offline segments, synthetic data and agent-operated review. Old unversioned demo/deck remain historical fixture-era assets and should not be submitted as current evidence.
